# mapping_forest_policy_and_economics
Code to download, compile and analyze SCOPUS metadata on this topic

Data is located here: https://zenodo.org/records/22872811

The analyze code is staigth-forward, the code on data download and compiling is not. 
The first part of the script for data analysis is to filter the papers from the sampling frame to the sample, i.e. to the field of forest policy and economics. 
I did not publicly share the sampling frame data - contact me to get it. 
The actual analysis starts from about half of the script. 
The dataframe that is uploaded to Zenodo matches to what is labeleld 'df_filtered_for_oldest' in the script. 
The edgelists / graphs that are uploaded to Zenodo match to what is labeled 'graph_filtered_by_communities' in the script. 

The code on data data download and compiling takes JSON data per paper from SCOPUS API, and then builds a +/- 3 snowball network centered on papers published in Journal Forest Policy and Econmoics. I don't upload these JSONs, you'd have to have SCOPUS licencse for these. 

Here is a technical summary of the script: 
The data source was SCOPUS API, while analysis was conducted in Python programming language. Data was compiled by two types of queries, both of which produce responses in JSON format. JSON is a is an open standard file format and data interchange format that uses human-readable text to store and transmit data objects consisting of name–value pairs and arrays. Data per paper was loaded as a nested dictionary, where name-value pairs are defined as dictionaries’ keys (e.g. you’d have to query ‘references’ within the dictionary to get a list of individual references of the queried paper, where each reference of the queried paper has separate information such as title, authors and full reference located within the nested dictionary). The first one is ‘abstract’, which provides meta-data on the queried paper by DOI (Digital Object Identifier), its abstract, and information on the papers referenced by the queried paper. From the results of this query, we formed both the Snowball + networks and a meta-data table, which hosts information such as title, authors, DOI, year, funding sources, abstract, etc. The second form of query was ‘REFEID’, where papers were queried by their EID (Scopus Electronic Identifier). This query produces a JSON file with a nested dictionary of all papers cited by the queried paper. Almost all references (approximately 95%) have a DOI, which includes all scientific journal articles, almost all scientific books, and most of the grey literature (e.g. technical reports). EID is a more restrictive identifier, which includes all (or almost all) scientific journal articles, and almost all scientific books, but it’s coverage of grey literature is substantially lower. DOI-based query produces all results in a single JSON. EID based query of citations produces JSON of up to 200 citations. If the queried paper has been cited by more than 200 other publications, then this has to be parsed-out in chunks of 25 citations. 
First we queried by DOI up to Snowball +3 sample, then by EID up to Snowball -3 sample, then we collected meta-data (including abstracts) all papers identified only in the Snowball – part of the sampling, and then we queried by EID additionally the papers that were identified only in the Snowball + part of the sampling (i.e. by DOI). In this way, we wanted to capture the co-citation network of the papers two times, not to miss any. This resulted with over a million downloaded files. We then constructed edgelists from DOI and EID queries. The overlap was 99.1%. Then single edgelist was made by deleting the duplicates. Edgelist was based on DOI, as it’s more encompassing identifier. Edgelist is a list of pairs of DOIs, where the first one is the sender of the citation (a paper referencing another paper), and the second one is the receiver of the citation (a paper being referenced by the first one). 
Given that almost all real large-scale network tend to have power-law distribution of degrees (Barabási and Albert, 1999) and small-world characteristics (Watts and Strogatz, 1998), on average any member of the network can reach any other member of the network in 6-16 degrees; regardless of the network’s size. We went for three degrees of separation in ‘both ways’; i.e. forward and backwards. The sheer size of the data-set we have performed too many snowball steps; covering twice the span all forestry research. SCOPUS data-set is not perfect. For example, when we manually checked at all the papers that cited Weiss et al, 2019, we saw that two of them have EID but no DOI. This should not be the case. Over 100 papers have been checked manually like this, and this is the only instance where this has been found. But given the large number of papers, it’s certain that there are more instances like these. Query by EID is very reliable, as the DOI and EID of the papers that cite the queried paper are located behind a separate key within the dictionary of the response. In query by DOI, that’s the case in about 90% of the cases. For the remaining 10%, the DOI of the paper referenced by the queried paper is located at the end of the full reference (text), behind the last comma. And as such, it needed to be parsed-out manually. They were also ‘cleaned’ by discarding DOI labels that don’t match the DOI format (e.g. shorter than 8 characters, don’t start with % or end with a file type, have page-numbering like patterns, etc.). The remaining DOI assignments are also manually checked. The papers that don’t have DOI are matched to meta-data file of all the sampled papers as based on title, while ignoring empty spaces and special characters. The edgelist is then cleaned of invalid full references – those which don’t have a title or a full reference, those labeled as ‘INVALID CITATION’ by SCOPUS, those which are illogically long (more than 500 character) or short (shorter than 30 characters, as based on manual inspection). The papers that still don’t have a (valid) DOI were then API queried to Crossref data-base as based on the full reference. On the example of snowball +1 network, total of 10% of references did not have a DOI assigned. From these 10%, 27% (or about 3% of total) did not have a DOI in Crossref. Of those which did, (i.e. 7% of total), DOI’s from Crossref did not produce hits in SCOPUS in 79% of cases. In the end, this results in about 6% of loss of references from the DOI queries. Each step of data compilation was manually checked with at least 50 examples (e.g. opening PDFs of the paper, and then querying DOI’s from the list of references and cross-checking it against compiled edgelist). Compiled edgelist was also compared to meta-data file, to see that all the papers in the meta-data file are listed both as senders and receivers in the edgelist; i.e. to ensure that all the relevant data has been downloaded. JSON files from DOI and EID queries were saved as lists, where indexes in the lists of individual papers were saved as separate columns to the meta-data file. In this way we assured that each paper was queried both by EID and DOI.
